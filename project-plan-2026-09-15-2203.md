## Goal

Replace the current `phase_order` + `phase_update_repeats` + `*_budget` scheme with a nested loop: `N_LL` low-level GRPO iterations inside each of `N_HL` high-level iterations. Each phase gets its own optimizer, LR scheduler, prompt stream and GRPO group size. Prompt batch sizes are *derived* from the dataset: LL uses `ceil(D/N_LL)`, HL uses `ceil(D/N_HL)`. Rollouts for every iteration come from the policy as updated by the previous iteration.

**Call graph for one phase update today** (keep this shape in `_run_phase_iteration`):

1. `_pop_gen_batch` → `generate_sequences` (`rollout_n_override` = budget / later `group_size`)
2. reward + old_log_prob + optional ref/critic (`_phase_rollout_to_scored_batch`)
3. `compute_advantage` (GRPO, `num_repeat=phase_rollout_n`)
4. `update_actor` with phase knobs stuffed into `meta_info` (kl, clip flags, advantage_algorithm, entropy); the active-phase scheduler always steps
5. log / dump / maybe val / maybe ckpt
6. `global_steps += 1`

**Step-accounting bug:** `total_training_steps = len(dataloader) * total_epochs` but `global_steps` increments once per *phase update*. Two active phases consume half the prompt batches: `total_epochs: 2` over D=10,000 at batch 128 → 156 steps = 78 cycles ≈ **one** epoch, not two. New accounting: `N_HL * (N_LL + 1)`, one prompt batch per global step.

## Target loop

```
for hl_cycle in range(N_HL):
    for ll_iter in range(N_LL):
        batch = next(LL iterator)          # ceil(D/N_LL) prompts
        rollout G_ll, reward, GRPO adv
        LL optimizer + LL scheduler step   # then fetch next chunk (on-policy)
    batch = next(HL iterator)              # ceil(D/N_HL) prompts
    rollout G_hl, reward, GRPO adv
    HL optimizer + HL scheduler step
    validate / checkpoint gate
```

Total global steps `= N_HL * (N_LL + 1)`.

## Locked decisions

- **Nesting:** `for _ in range(N_HL): { for _ in range(N_LL): LL_iteration }; HL_iteration }`. Total global steps `= N_HL * (N_LL + 1)`.
- **Prompt streams:** independent shuffled iterator per phase, each cycling over the full dataset.
- **Batch sizes are derived, not configured.** `D = len(train_dataset)`. DataLoader `batch_size = (D // num_iters[phase]) // world_size * world_size`, `drop_last=True` (amended 2026-09-15 with user approval, S3). Original decision was `ceil(D / num_iters)` with `drop_last=False`; that is unimplementable because every worker-group call chunks the batch across ranks and `DataProto.chunk` asserts `len(batch) % world_size == 0` (auto-padding is off and would duplicate samples into training). Flooring to a multiple of `world_size` keeps every batch uniform and rank-divisible for any `D`; each pass leaves `< batch_size + (D mod batch_size)` prompts unused, re-permuted on the next pass.
  - LL: `N_LL` inners = one full LL pass over D per outer cycle. LL sees D once per outer cycle, `N_HL` times over the run.
  - HL: one HL update per outer cycle. `N_HL` outers = one full HL pass over D for the whole run.
- **On-policy chain:** after an LL iteration finishes its optimizer step(s) on chunk `k`, chunk `k+1` is rolled out from the *updated* policy. Same for HL across outer cycles. Already how `generate_sequences` works (FSDP→vLLM resync); only the fetch point changes.
- **Mini / micro inside a chunk:** per-phase knobs. Several optimizer steps on already-collected rollouts are allowed (classic PPO). Fresh rollouts only when moving to the next chunk.
- **Independent optimizers:** two `AdamW` over the same FSDP parameters; independent moments and LR schedules. Horizons: HL=`N_HL`, LL=`N_HL*N_LL`.
- **GPU packing is a config choice, not a code path.** 8 GPUs. Tune `N_HL`, `N_LL`, `group_size`, mini/micro-batch so one iteration (`ceil(D/N_*) * G` sequences) plus the PPO update fit. **Do not** add `chunk_prompts` / rollout-side gradient accumulation. OOM → raise `N_*` or lower `G` / micro-batch. Fail loud.
- **Both phases always run.** Assert `N_HL >= 1` and `N_LL >= 1` (and `<= D`). No skip path, no `N_*=0`.
- **`mask_categories` stay under `rollout`.**
- **No GPU runs from the agent.** Verify with import checks, `bash -n`, Hydra dry-compose.
