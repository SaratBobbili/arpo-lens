## Goal

`project-plan-2026-09-15-2203.md` restructured ECHO RL into a nested loop (`N_LL` low-level iterations inside each of `N_HL` high-level iterations) with per-phase optimizers and derived prompt batch sizes, and it was verified only by compose/import/unit-level checks — never on GPU. This Goal makes that code launchable the way the pre-refactor scripts were: one self-contained script per model that a human reads top-to-bottom, sets a handful of values in, and runs. The difference from the old scripts is that the ~120-line Hydra override list is no longer copy-pasted per model; it lives once in `train.sh`, the shared flat profile supplies defaults, and the per-model script passes only its deltas as `key=value` arguments.

First target model: `Qwen2.5-7B-Instruct-lr5e8-ep1` (LLaMA-Factory ECHO cold-start SFT, gentle lr 5e-8, 1 epoch) with `BingSearchTool`.

### Derived sizes for the Qwen2.5-7B run

With D=10000, `num_iters=79`, 8 ranks: prompt batch `= (10000 // 79) // 8 * 8 = 120`. At `group_size=16` that is 1920 sequences per iteration (the old scripts ran `train_batch_size=128 × rollout_n=16 = 2048`, so this is the same ballpark that fit before). `ppo_mini_batch_size=16` prompts → `16*16/8 = 32` sequences per rank per mini batch, so a 240-sequence rank shard splits `[32×7, 16]`. Total global steps `= 79 * (79 + 1) = 6320`; `save_freq`/`test_freq: 5` count outer cycles.

### S2 — Qwen launch script + train.sh override passthrough

**Goal:** A human can start the Qwen2.5-7B ECHO RL run with `bash train_qwen7B.sh`, reading one short script that shows exactly what is model-specific, with everything else coming from the shared profile.

**Why the code looks this way:** The refactor replaced the old per-model scripts (each carrying its own full copy of the Hydra override list, which is how `phase_order` / budget flags drifted between them) with `train.sh <profile.yaml>`. But `train.sh` only ever reads `$1`, so the *only* way to vary a run was to write a whole new flat profile — which reintroduces the duplication the profile was meant to remove. Adding a validated `key=value` passthrough makes the base profile the defaults and the per-model script the diff.

**Read first:**

- `ECHO/training/scripts/train.sh` — `VALID_LAUNCH_KEYS`, the validator `python3 -c`, the YAML→shell `eval`, the path construction below it, the `CONFIG_SNAPSHOT_DIR` block
- `ECHO/training/training_config/echo_3B_ll_hl_grpo.yaml` — which keys already carry the values a Qwen run wants
- `ECHO/training/scripts/old/ECHO_2.5_7B_Reasoning_1node_v1_ll_hl.sh` — the readability target and the prior 7B run identity
- `ECHO/training/scripts/secrets.sh` — what must **not** be duplicated into the new script

**Do:**

1. In `train.sh`, after the YAML `eval` and **before** the "Construct full paths from roots" block, consume `"${@:2}"` as `key=value` overrides: reject any key not in `VALID_LAUNCH_KEYS` (same fail-loud spirit as the profile validator), then assign the uppercased key. Overrides must land before `TRAIN_FILES` / `ACTOR_MODEL_PATH` / `SEARCH_CACHE_PATH` / `SAVE_PATH` are derived, or overriding `actor_model_subpath` / `experiment_name` silently does nothing.
2. Record the overrides in the run snapshot next to `launch_config.yaml` so a checkpoint folder still fully describes its run.

Only pass what differs from the base profile — do not restate the 60 keys the profile already sets. Allow env overrides (`EXPERIMENT_NAME=... bash train_qwen7B.sh`) so a sweep does not need a new file.
4. Do not hard-code `BRIGHTDATA_API_KEY` / `WANDB_API_KEY`; they come from `secrets.sh`.

## Locked decisions

- **One script per model, deltas only.** The per-model script passes `key=value` overrides; the shared flat profile holds defaults. No new full profile per model, no copy of the Hydra override list.
- **`train.sh` stays the single owner of the flat-key → Hydra-dotted-path mapping**, including the `VALID_LAUNCH_KEYS` allowlist. Overrides are validated against that same allowlist and fail loud, matching how unknown profile keys already fail.
- **Base profile reused in place**: `training_config/echo_3B_ll_hl_grpo.yaml`, not renamed, despite the historical name and its Llama `actor_model_subpath` default. Per-model scripts override run identity and model.
- **First model:** `Qwen2.5-7B-Instruct-lr5e8-ep1`.
- **Search backend:** `BingSearchTool`. The operator supplies `BRIGHTDATA_API_KEY` in `secrets.sh` (currently `""`; the real key is on the commented line directly above, and in `scripts/old/ECHO_2.5_7B_Reasoning_1node_v1_ll_hl.sh:100`). The RAG sidecar path in `train.sh` stays available but unused.
- **Search cache is a query→SERP map and model-independent**, so runs share the largest existing cache for hit rate rather than starting an empty per-model file. `merge_search_cache_postrun.py` exists for merging if a run ever writes its own.
- **Secrets only in `secrets.sh`.** Never in a tracked launch script or profile.
- **No GPU runs from the agent.** Verify by `bash -n`, launch-key validation, Hydra dry-compose.
- **Do not touch** `ECHO/training/scripts/old/` or prior Goal plans (`project-plan-2026-09-15-2203.md` and earlier).
