## Goal

Wandb today duplicates nearly every signal under `high_level/` and `low_level/`, which obscures whether the **shared policy** is healthy. Prune unnecessary phase-specific stats, keep a small phase-owned set (optimizer / update), and add unprefixed `policy/*` indicators that answer: is reward rising, is format/tool behavior sane, is entropy/KL/advantage signal alive, is the update stable.

## Architecture / codebase map

```
RayECHOTrainer._train_phase_iteration
  -> gen metrics: tools/{total,successful}_calls -> policy/tools_*
  -> scorer metrics -> policy/{reward_mean,f1_mean,bad_format_rate,...}
  -> compute_data_metrics filtered -> policy/{response_length_*,advantage_std}
  -> actor update: phase-owned keepers prefixed; ppo_kl/pg_clipfrac -> policy/*
  -> timing_s/step + unprefixed perf/* only
  -> logger + _dump_logging_data(_LOGGING_SPEC)  # low_level|high_level|policy
```

Key files:

- `ECHO/training/echo_ray_trainer.py` — prefixing, scorer metrics, entropy log, `_LOGGING_SPEC`, `_dump_logging_data`
- `ECHO/training/echo_dp_actor.py` — `actor/pg_loss`, `opefo_*`, `entropy_reg_loss`, `kl_loss`, clipfrac
- `ECHO/training/echo_fsdp_workers.py` — `actor/lr`, `perf/*`
- `ARPO/verl_arpo_entropy/verl/trainer/ppo/metric_utils.py` — `compute_data_metrics` / timing (prefer filter at ECHO call site, do not fork verl)
- `ECHO/training/docs/logging_readme.md` — user-facing cheatsheet
- `ECHO/training/analysis/plot_training_log.py` — reads `_LOGGING_SPEC` JSONL paths

### DROP (do not emit to wandb / JSONL)

- `reward/score_mean` — duplicate of `reward/effective_reward_mean`
- `reward/format_pass_rate` — `1 - bad_format_rate`
- `reward/effective_reward_mean` as a *second* name once `policy/reward_mean` exists (keep one name only)
- `critic/score/{mean,max,min}` — duplicates scorer reward stats under GRPO
- `critic/rewards/{mean,max,min}` and `critic/returns/{mean,max,min}` — redundant with advantages under outcome GRPO
- `critic/advantages/{max,min}` — keep spread via std (or mean abs) only
- `prompt_length/{mean,max,min,clip_ratio}` — not algorithm-health; rare debug only
- `global_seqlen/*` and `training/balance_*` — DP load-balance noise
- `tools/{python,search}/avg_time`, `tools/total_execution_time`, `tools/avg_execution_time`, `tools/max_execution_time`, `tools/total_retries`, `tools/max_retries` — infra, not policy health
- `training/group_size`, `training/num_prompts` every step — constants (config already knows)
- `actor/opefo_pg_loss` — duplicate of `actor/pg_loss` on OPEFO path
- `actor/opefo_frac_pos`, `actor/opefo_frac_neg` — secondary; λ* + mags + ΔH_net suffice
- `actor/pg_clipfrac_lower` — niche dual-clip diagnostic
- Per-stage `timing_s/<phase>_*` and `timing_per_token_ms/*` from the default health view (keep `timing_s/step` + existing unprefixed `perf/*` only for throughput)

### KEEP phase-prefixed (`high_level/` | `low_level/`) — phase-owned only

- `actor/lr` — independent AdamW / schedule per phase
- `actor/pg_loss` — that phase's update scalar
- `actor/grad_norm` — that phase's backward
- `actor/entropy_reg_loss` (+ coef) — only when `reg_coeff > 0` for that phase
- `actor/opefo_{lambda,delta_H_net,pos_mag,neg_mag}` — only when that phase has `opefo.enabled` (phase can differ)

### PROMOTE / COMPUTE as whole-policy (`policy/*`, no phase prefix)

Emitted every training step from the phase that actually ran (same cadence as today), but **shared namespace** so wandb shows one curve for π_θ:

| Key | Why it confirms the algorithm |
|-----|-------------------------------|
| `policy/reward_mean` | Training task signal (scorer mean) |
| `policy/f1_mean` | Task quality without format −1 |
| `policy/bad_format_rate` | Format collapse |
| `policy/format_valid_rate` | Structure gate |
| `policy/no_tool_rate` | Degenerate no-search behavior |
| `policy/in_group_reward_std` | GRPO signal alive (≈0 ⇒ dead groups) |
| `policy/advantage_std` | Post-normalize advantage spread |
| `policy/entropy` | Mean Shannon H on **full response mask** (not phase loss_mask) — true policy peakedness |
| `policy/ppo_kl` | Step size vs rollout policy |
| `policy/pg_clipfrac` | Trust-region pressure (0 on pure OPEFO) |
| `policy/rollout_probs_diff_mean` | vLLM ↔ actor agreement |
| `policy/response_length_mean` | Length drift |
| `policy/response_length_clip_ratio` | Truncation |
| `policy/tools_total_calls` | Tool use volume |
| `policy/tools_successful_calls` | Tool reliability |
| `val-core/*` | Already global — unchanged primary quality dial |

Optional later (not S3 required): `policy/entropy_tool` / `policy/entropy_reason` via existing category masks if full-mask entropy is too coarse.
